## 0. 技术选型

| 关注点 | 选型 | 说明 |
|---|---|---|
| 前端框架 | React + TypeScript + Vite（Qoder Sites  bundled React starter） | 用 `create-site.mjs` 初始化于 `D:\AI_WorkStation\my-schedule`；静态构建输出到 `dist/` |
| 路由 | 哈希路由自管理（`#/home` `#/schedule` `#/tasks` `#/campaigns` `#/settings`） | 5 个 Tab 页 + 战役详情子视图；不引入 react-router，保持依赖最小 |
| 状态管理 | React Context + useReducer 全局 Store（`src/store.tsx`） | 单一数据缓存 + CRUD wrapper；不引入 zustand/redux |
| 样式 |  starter 自带样式基座 + 自定义 CSS（`src/styles.css`） | 响应式断点 768px；手机底部 Tab / 桌面顶部导航 |
| 服务端 | Qoder Sites 单个 `app` Edge Function（Deno，`functions/index.ts`） | 浏览器仅调用同源 `/functions/v1/app?action=...`；action 路由模式 |
| 数据库 | Sites 托管 Supabase（Function 侧 adapter 注入 `supabase` 客户端） | schema 通过 sites-management 迁移工具创建；见 §2 |
| 访问策略 | 匿名读写（anonymous read_write） | **已确认的风险接受**：无登录产品，隐私靠链接不公开（用户 2026-09-25 确认） |
| 部署 | Qoder Sites：`prepare_site`（webDirectory=dist, functionDirectory=functions, spa=true, databaseAccess=read_write）→ `publish_site` | 发布流程遵循 sites-hosting 技能 |
| 本地开发 | Vite dev server + Function 本地代理 → `dev/local-server.mjs`（内存 fake supabase + 种子数据） |  fixture 仅本地，不进入 dist/functions |
| 提醒 | 前端定时器（每分钟检查）+ Notification API | 页面关闭不推送（PRD 已知限制） |

**不引入**：react-router、zustand、UI 组件库（除 starter 自带）、日期库（自写 `lib/date.ts`）。

## 2. 数据库 schema（迁移 v1，一次提交）

```sql
create table semesters (
  id uuid primary key, name text not null,
  start_monday date not null, total_weeks int not null,
  is_current boolean not null default false, created_at timestamptz default now());
create table period_slots (
  id uuid primary key, slot_no int not null unique,
  start_time text not null, end_time text not null);          -- "08:00" 格式
create table holidays (
  id uuid primary key, name text not null,
  start_date date not null, end_date date not null);
create table courses (
  id uuid primary key, semester_id uuid not null references semesters(id),
  name text not null, teacher text not null default '',
  weekday int not null,            -- 1-7
  start_period int not null, end_period int not null,   -- 1-14
  week_rule text not null,         -- JSON: {"ranges":[[2,17]],"parity":null|"odd"|"even"}
  location text not null default '', color text not null default '',
  note text not null default '');
create table campaigns (
  id uuid primary key, name text not null, goal text not null default '',
  deadline date, color text not null default '', created_at timestamptz default now());
create table tasks (
  id uuid primary key, title text not null, date date not null,
  start_time text, end_time text,
  category text not null default '生活', priority text not null default '中',
  repeat_rule text not null default '{"type":"none"}',
  reminder text not null default 'none',      -- none|on_time|10|30|60
  done boolean not null default false,
  campaign_id uuid references campaigns(id),
  note text not null default '', created_at timestamptz default now());
create table task_completions (          -- 重复日程的按次完成记录
  id uuid primary key, task_id uuid not null references tasks(id),
  date date not null, unique (task_id, date));
create table countdowns (
  id uuid primary key, name text not null, target_date date not null);
create table settings (
  id int primary key default 1,
  remind_minutes int not null default 10,
  overlay_repeat boolean not null default true,
  check (id = 1));
```

accessPolicies：以上全部表 anonymous = read + write（已确认的私密链接方案）。

**重复规则 JSON 约定**（`tasks.repeat_rule`）：
`{"type":"none"}` / `{"type":"daily"}` / `{"type":"weekly","weekdays":[1,4]}` / `{"type":"biweekly","weekday":1,"anchor":"2026-09-07"}` / `{"type":"weeks","weeks":[3,5],"weekday":2}`。
**周次规则 JSON 约定**（`courses.week_rule`）：`{"ranges":[[2,9],[10,11]],"parity":null}`，parity 作用于范围内周次。

## 3. Function action 契约（`functions/handler.mjs`）

统一入口 `GET/POST /functions/v1/app?action=<name>`；POST body 为 JSON；所有入参服务端白名单校验；错误返回 `{error: code}` 安全码，不泄漏 SQL/原始错误。

| action | 方法 | 说明 |
|---|---|---|
| `bootstrap` | GET | 一次性返回全部数据 `{semesters, periodSlots, holidays, courses, campaigns, tasks, completions, countdowns, settings}`；前端 Store 冷启动唯一读 |
| `semester.save` / `semester.setCurrent` / `semester.delete` | POST | 新建/编辑学期；切换当前（事务性：先全置 false 再置 true，两次调用）；删除仅允许非当前学期 |
| `holiday.save` / `holiday.delete` | POST | 节假日增改/删 |
| `period.save` | POST | 批量更新 14 节节次时间（整表替换式 update） |
| `course.save` / `course.delete` | POST | 课程增改/删 |
| `task.save` / `task.delete` | POST | 日程增改/删 |
| `task.batch` | POST | `{ids, op: "done"\|"undone"\|"delete"\|"move"\|"category", payload}`；move=`{date}`；重复任务 done 写 task_completions |
| `task.complete` | POST | `{id, date, done}`：非重复写 tasks.done；重复写/删 task_completions 行 |
| `campaign.save` / `campaign.delete` | POST | 战役增改/删（删除时子计划 campaign_id 置空） |
| `campaign.attach` | POST | `{campaignId, taskIds}` 挂载；`{taskIds}` + `campaignId:null` 脱离 |
| `countdown.save` / `countdown.delete` | POST | 自定义倒计时增/删 |
| `settings.save` | POST | 更新单行设置 |
| `seed.ifEmpty` | POST | 仅当 semesters 为空时写入 §5 种子数据（首跑初始化） |

实现要点：handler 内 `validate*` 纯函数做字段白名单与类型/长度校验；ID 一律服务端 `crypto.randomUUID()` 生成；所有列表读显式列名 + 有界 limit。

## 4. 阶段划分

### 阶段 2：数据层、schema、种子数据与日期引擎（任务 #2）
**交付物**：云端 schema v1 + 种子数据入库 + 前端 Store 与日期计算可用。
- 通过 sites-management 创建并应用迁移 v1（§2 SQL + accessPolicies）。

- handler 实现 §3 全部 action。

- `src/store.tsx`：bootstrap 拉取 + 缓存 + 各实体 CRUD wrapper（乐观更新 + 失败回滚 + 刷新队列）。
**依赖**：阶段 1。
**完成标准**：`seed.ifEmpty` 执行后 `bootstrap` 返回完整数据；`date.ts` 关键用例手测通过（2026-09-25=第3周周五；第12周周二3-5节为新时代实践教育而非计算机基础；10/1 命中国庆；每周三重复日程在第4周周三展开）。

## 6. 防跑偏守则

1. 每个阶段结束先跑该阶段「完成标准」，未过不进入下一阶段。
2. 新增文件/依赖前对照 §0/§1：不引入计划外依赖；确需调整先改本文件。
3. 所有服务端写操作必须走 §3 action 契约 + 白名单校验；前端不得直连数据库。
4. 种子数据只允许来自 `parsed_schedules.txt` 与校历.jpg；发现数据冲突以 PRD 5.2 为准并回报用户。
5. UI 文案用中文；不写营销式文案；空/加载/错误态每页必备。
6. 任何 PRD 未定义的新需求 → 记入「待确认」清单问用户，不擅自实现。
