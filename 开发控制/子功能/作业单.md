# 作业单（作业汇总页）技术方案

> 状态：已实施（2026-09-30；本地测试 phase1–8 共 284 项全部通过）
> 日期：2026-09-30
> 关联功能：作业单（已上线的单课程作业列表）

## 1. 背景与现状

### 1.1 用户问题
「我的作业列表应该在哪里查看？」

### 1.2 现状分析
作业功能目前**只能按课程查看**，入口很深：

```
课表页 → 点击某个课程块 → 课程详情弹窗 → 「课程作业」区块
```

已有资产（无需重做）：

| 层 | 现状 | 结论 |
| --- | --- | --- |
| 数据库 | `app.homework` 表（id/title/course_id/due_date/description/completed/created_at），anonymous 读写策略已配置 | 无需迁移 |
| 后端函数 | `homework.save` / `homework.delete` / `homework.complete` 三个 action；`bootstrap` 已返回全部 homework | 无需改动 |
| 前端状态 | `store.tsx` 已有 `homework` 状态与 `saveHomework` / `deleteHomework` / `completeHomework` | 无需改动 |
| 前端组件 | `HomeworkList.tsx` 已支持不传 `courseId` 的「全部作业」模式（含添加表单、编辑、完成切换、删除、按截止日期排序） | 可直接复用 |

**缺口只有一个：没有承载「全部作业」的页面和导航入口。**

## 2. 方案设计

### 2.1 新增「作业」独立页面（推荐）

- 新建 `src/pages/HomeworkPage.tsx`，路由 hash 为 `#/homework`
- 页面主体直接复用 `<HomeworkList showCompleted />`（不传 courseId，即全量模式）
- 在 `App.tsx` 的 `pages` 映射中注册 `homework: HomeworkPage`
- 在 `Nav.tsx` 的 `TABS` 中新增 `{ id: "homework", label: "作业", icon: "📚" }`
  - 桌面顶部导航与移动底部导航共用 TABS，一处修改两端生效
  - 移动端 6 个 tab（首页/课表/日程/作业/战役/设置），375px 宽下每个约 62px，可容纳

**否决的备选方案：**
- ~~作为「日程」页内的一个 tab~~：日程页已有自己的视图切换逻辑，混入作业会让 TasksPage 复杂化；用户明确要求「一个作业汇总的页面」
- ~~只放首页卡片~~：首页空间有限，无法承载添加/编辑/筛选等完整操作

### 2.2 HomeworkPage 增强（在复用基础上小幅扩展）

按截止日期分组展示，突出紧急程度：

```
┌─────────────────────────────┐
│  作业           [+ 添加作业] │
│  ⚠ 已逾期 (2)               │  ← 红色标记，due_date < 今天 且未完成
│  📌 今天到期 (1)             │
│  本周内 (3)                  │  ← 今天 < due_date ≤ 本周日
│  之后 (4)                    │
│  无截止日期 (1)              │
│  ─────────────              │
│  ✓ 已完成 (折叠区，默认收起)  │
└─────────────────────────────┘
```

每条作业卡片显示：标题、所属课程名（复用 `getCourseName` 逻辑）、截止日期、完成勾选、编辑/删除按钮。

顶部增加**课程筛选 chips**（全部 / 各课程名），点击过滤 `course_id`。

### 2.3 组件改造策略

两种实现路径，推荐 A：

- **A（推荐）：扩展 HomeworkList**
  给 `HomeworkList` 增加可选 prop `grouped?: boolean`。`grouped=true` 时按 2.2 的分组渲染；不传时保持现有平铺列表行为，课程详情弹窗内的用法完全不受影响。
- B：HomeworkPage 自己写分组渲染，只复用 HomeworkForm
  代码更独立但会重复卡片渲染逻辑，不推荐。

### 2.4 入口联动（可选加分项）

- 首页（HomePage）若有「今日概览」类卡片，可增加「今日到期作业 N 项」一行，点击跳转 `#/homework`
- 课程详情弹窗保持现状（按课程过滤的作业列表）

## 3. 数据与接口

**无任何后端改动。** 全部数据来自 `bootstrap` 已返回的 `homework` 数组，前端内存中分组/筛选。

分组判定逻辑（前端纯函数，放 `src/lib/date.ts` 或页面内）：

| 分组 | 条件 |
| --- | --- |
| 已逾期 | `!completed && due_date && due_date < today` |
| 今天到期 | `!completed && due_date === today` |
| 本周内 | `!completed && today < due_date ≤ 本周日` |
| 之后 | `!completed && due_date > 本周日` |
| 无截止日期 | `!completed && !due_date` |
| 已完成 | `completed`（折叠） |

### 验收标准

1. 桌面与移动端导航均出现「作业」入口，点击进入 `#/homework`
2. 页面显示全部课程的作业（不再需要先点进某门课）
3. 逾期作业有醒目红色标记且排在最前
4. 已完成作业默认折叠，可展开
5. 课程筛选 chips 过滤正确
6. 添加/编辑/完成/删除操作与课程详情内行为一致，刷新后持久化
7. 课程详情弹窗内的「课程作业」区块行为不变（回归）
8. phase1–7 全部测试仍通过，phase8 新增测试通过
