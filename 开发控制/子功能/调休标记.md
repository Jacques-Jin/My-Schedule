# 调休标记（单日放假 / 补课）技术方案

> 状态：仅计划，未实施
> 日期：2026-09-30
> 关联功能：课表（周视图 / 日视图）、校历节假日、首页今日概览、日常活动横带

## 1. 背景与现状

### 1.1 用户诉求

「手动标记某一天是放假还是正常上课，因为我们有时会有调休之类的事。」

### 1.2 现有机制

| 层 | 现状 | 能力边界 |
| --- | --- | --- |
| 数据 | `app.holidays`（id uuid / name / start_date / end_date），线上 `schema_version = 3` | 只能表达「某段日期放假」，无法表达「某天要上课」 |
| 解析 | `src/lib/date.ts`：`holidayOn(date, holidays)` 判放假；`courseOccursOn(course, date, semester)` 按 `weekday` + `week_rule` 判上课 | 两者互不知道对方之外的例外；周六周日即使学校安排补课，也不会显示任何课程 |
| 渲染 | `SchedulePage.tsx`：`getHolidayForDate` 命中 → 表头红底 + 显示假期名、单元格 `.holiday-cell`、**课程块整天不渲染**、日常横带该列清空；`DayView` 显示放假横幅并隐藏课程分组 | 只能「减法」（把课去掉），不能「加法」（把课补上） |
| 后端 | `holiday.save` / `holiday.delete`；`bootstrap` 返回 `holidays`；`data.export/import` 覆盖 10 张表 | 无单日覆盖相关 action |
| 入口 | 设置页 →「校历节假日」可增删假期区间 | 入口深，且必须填起止日期，不适合临时调休 |

### 1.3 缺口

现有模型缺一层**单日覆盖（day override）**：

1. **工作日临时放假**（校运会、考试、讲座停课）：`holidays` 勉强能做（起止同一天），但要绕到设置页，且无法从课表上直接点。
2. **周末 / 假期中补课**（如「10 月 10 日周六补周三的课」）：**完全无法表达**——周六没有 `weekday=6` 的课程，即使强行取消假期，格子依然是空的。

## 2. 需求定义

给每一天一个可选的「覆盖标记」，两种类型：

| 类型 | 语义 | 渲染结果 |
| --- | --- | --- |
| `holiday`（放假） | 这天不上课 | 隐藏当天全部课程与日常活动；表头红底 + 标记名；日视图显示放假横幅 |
| `classday`（上课 / 补课） | 这天要上课 | 强制显示课程；可指定「按周几的课表上课」；表头蓝底 + 「补」角标 |

`classday` 附带一个可选项 **`follow_weekday`（1–7 或空）**：

- 填 3 → 该天显示**当周周三**的全部课程（典型调休：周六补周三的课）
- 留空 → 按该天真实星期解析（典型用法：把假期区间里的某一天恢复成正常上课日）

**周次一律按真实日期计算**：10 月 10 日（第 5 周周六）补周三的课，显示的是**第 5 周**周三的课，不会错位到别的周。

### 2.1 解析优先级（唯一裁决顺序）

```
resolveDayType(dateStr, holidays, overrides) → { isHoliday, label, effectiveWeekday, source }

1. 命中 override 且 kind = holiday   → isHoliday = true，label = 标记名（默认「放假」）
2. 命中 override 且 kind = classday  → isHoliday = false，effectiveWeekday = follow_weekday ?? 当天星期
3. 命中 holidays 区间               → isHoliday = true，label = 假期名
4. 其余                            → isHoliday = false，effectiveWeekday = 当天星期
```

`override` 永远压过 `holidays`；一天最多一条 override（同一天重复标记 = 覆盖旧的）。

## 3. 技术方案

### 3.1 数据模型：新表 `app.day_overrides`（schema_version 3 → 4）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `uuid` | 主键，由 handler 用 `crypto.randomUUID()` 生成（平台 DDL 不支持 DEFAULT） |
| `date` | `text` | `YYYY-MM-DD`。**平台受限 DDL 不支持 `date` 类型**，与 `holidays.start_date` 一样用 text |
| `kind` | `text` | `'holiday'` \| `'classday'`，取值由 handler 校验（受限 DDL 不支持 CHECK/DEFAULT） |
| `follow_weekday` | `integer` | 可空；仅 `classday` 有意义，取值 1–7 |
| `name` | `text` | 可空；显示名，如「调休放假」「补周三的课」 |
| `created_at` | `timestamptz` | 由 handler 写入 `new Date().toISOString()` |

约束说明：

- **唯一性（一天一条）在 handler 层保证**：`dayOverride.save` 先按 `date` 删除旧记录再插入。平台受限 DDL 只允许 `CREATE TABLE` / `ALTER TABLE ADD COLUMN` / 普通 `CREATE INDEX`，不能建唯一索引。
- 建一张普通索引 `CREATE INDEX ... ON app.day_overrides (date)` 加速按日期查询（可选，数据量小，非必需）。
- 访问策略与 `holidays` 一致：`principal = anonymous`、`template = public`、`actions = [select, insert, update, delete]`（本项目无登录体系）。

迁移执行链路（实施时按此顺序，不可颠倒）：

1. `get_database(siteId)` 取**当前** `schema_version` 与 `schema_fingerprint`（现为 3 / `952ce1cc…`，实施时须重新读取，快照可能已刷新）
2. `create_database_migration`：`sql` = 建表（+ 可选索引），`accessPolicies` = 上面那条 anonymous 策略，`expectedSchemaVersion` / `expectedSchemaFingerprint` 用第 1 步的值，`requestId` / `clientMigrationId` 为新生成的稳定 UUID
3. **向用户说明变更内容与访问策略影响并取得授权**（`apply_database_migration` 要求授权覆盖 schema 与策略影响）
4. `apply_database_migration`：带上一步 review 返回的 `migrationId`、`expectedRevision`、`expectedSchemaVersion`、`expectedSchemaFingerprint`、`sqlSha256`、`confirm: true`；轮询返回的 operation 至 succeeded
5. 再次 `get_database` 确认 `schema_version = 4`
6. 之后 `prepare_site` 的 `requiredSchemaVersion` 必须由 3 改为 **4**

### 3.2 后端接口（`functions/handler.mjs`）

| action | 入参 | 行为 |
| --- | --- | --- |
| `dayOverride.save` | `{ id?, date, kind, follow_weekday?, name? }` | `validateDayOverride` → 若带 `id` 走 update；否则**先删同 `date` 的旧记录**再 insert（补 `id`、`created_at`）→ 返回整行 |
| `dayOverride.delete` | `{ id }` 或 `{ date }` | 删除 → `{ deleted: true }` |
| `bootstrap` | — | `tables` 列表增加 `["day_overrides", "id,date,kind,follow_weekday,name"]`，返回值增加 `dayOverrides` 键 |
| `data.export` | — | `tables` 数组加入 `"day_overrides"` |
| `data.import` | — | 清表数组加入 `"day_overrides"`；`CREATED_AT_TABLES` 加入 `"day_overrides"`（`prep()` 才会补 `created_at`）；用 `buildMap("day_overrides")` 导入；**payload 缺该键时必须跳过而不报错**（向后兼容 9 月旧备份） |

新增校验函数 `validateDayOverride(p)`：

- `date` 必须匹配 `^\d{4}-\d{2}-\d{2}$`，否则 `invalid_date`
- `kind` 必须是 `'holiday'` 或 `'classday'`，否则 `invalid_kind`
- `follow_weekday` 允许 `null`/缺省；给了就必须是 1–7 的整数，否则 `invalid_follow_weekday`
- `kind = 'holiday'` 时忽略并清空 `follow_weekday`（避免脏数据）
- `name` 可选，限长（建议 ≤ 30 字符），超长 → `invalid_name`

`pick()` 白名单字段：`["date", "kind", "follow_weekday", "name"]`。

### 3.3 日期解析层（`src/lib/date.ts`）

新增：

```
export interface DayOverride {
  id: string; date: string; kind: "holiday" | "classday";
  follow_weekday: number | null; name: string | null;
}

export interface DayType {
  isHoliday: boolean;
  label: string;                 // 放假/补课显示名，正常日为空串
  effectiveWeekday: number;      // 1-7，课程匹配用的星期
  source: "override" | "holiday" | "normal";
}

export function overrideOn(dateStr: string, overrides: DayOverride[]): DayOverride | null
export function resolveDayType(dateStr: string, holidays: Holiday[], overrides: DayOverride[]): DayType
```

改动：

- `courseOccursOn(course, date, semester, effectiveWeekday?)` —— **新增可选第 4 参**，缺省时沿用 `date.getDay()` 原逻辑，保证所有旧调用点行为不变；传入时用 `effectiveWeekday` 与 `course.weekday` 比较，周次仍由真实 `date` 算出
- `holidayOn` / `weekIndexOf` / `expandTaskOn` **签名不动**（`expandTaskOn` 的调用方改为「先 `resolveDayType`，`isHoliday` 为真就不取日常」）
- `nextClassFrom`：**当前无任何调用点**（遗留代码）。本次不改签名，只在函数上方加一行注释说明「未接入 day override，调用前需自行处理」，避免将来误用

### 3.4 状态层（`src/store.tsx` + `src/lib/api.ts`）

- `store.tsx`：`State` 增加 `dayOverrides: DayOverride[]`；`initialState` 补空数组；`Action` 增加 `upsert_day_override` / `remove_day_override`（**按 `date` 去重**，不是按 id，因为 save 会替换同日期旧记录）；`StoreCtx` 增加 `saveDayOverride(data)` / `deleteDayOverride(params)`，沿用现有「乐观更新 + 失败 `refresh()`」写法（参照 `saveHoliday` / `deleteHoliday`）
- `api.ts`：`dayOverrideSave: (data) => requestJson("dayOverride.save", data)`、`dayOverrideDelete: (params) => requestJson("dayOverride.delete", params)`
- `bootstrap` 的返回结构变更会自动进入 `dispatch({type:"bootstrap"})`，无需额外处理

### 3.7 否决的备选方案

| 方案 | 否决理由 |
| --- | --- |
| 给 `holidays` 加 `kind` 列 | 语义混杂（假期表里存「上课」记录），且 `follow_weekday` 对假期无意义；新表更清晰，迁移成本相同 |
| 往 `courses` 表复制一份「补课课程」 | 数据冗余；改课表要改两处；无法自动跟随 `week_rule` 周次与单双周规则 |
| 只做设置页入口 | 用户诉求是在课表上直接标记，设置页入口太深 |
| 存 `localStorage` | 不跨设备同步，与「无登录 + 云端数据库」架构冲突 |
| 在 `settings` 表塞 JSON | `settings` 只有 `remind_minutes` / `overlay_repeat` 两列，加 JSON 列同样要迁移，却失去按日期查询与结构校验能力 |

## 6. 验收方案

### 6.1 验收标准

1. 周视图点击任意日表头弹出标记表单，日期已预填为该列日期
2. 标记「放假」后：该日课程全部消失、日常横带该列为空、表头红底并显示标记名、日视图显示放假横幅
3. 标记「上课」+「按周三课表」后：若该日是周六，则显示**当周**周三的全部课程；该周六原有的课程（若存在）不再显示
4. 补课日的周次正确：第 5 周的周六补周三 → 显示第 5 周周三的课（含单双周规则），不会串到第 4 或第 6 周
5. 假期区间内某天标记「上课」后，该天恢复显示课程，同区间其余天仍为假期
6. `follow_weekday` 留空时，行为等同「取消该天的假期」，课程按该天真实星期显示
7. 同一天重复标记会覆盖旧标记，`bootstrap` 后该日期只有一条记录
8. 清除标记后该天恢复默认解析（`holidays` + 星期 + 周次）
9. 首页今日卡片：今天被标记放假 → 显示放假且今日课程为空；被标记补课 → 显示对应课程
10. 设置页「调休 / 补课标记」列表按日期排序展示全部标记，可逐条删除，删除后课表立即恢复
11. 刷新页面 / 换设备打开站点，标记仍在（云端持久化）
12. `data.export` 含 `day_overrides`；导入不含该键的旧备份不报错
13. 回归：**没有任何标记时**，课表 / 首页 / 日程 / 提醒显示与改动前完全一致
14. 移动端 375px：表头可点击，Sheet 不溢出，标记后渲染正常

| 用例 | 断言 |
| --- | --- |
| `dayOverride.save` 新建 holiday | 返回 `id`，`kind = 'holiday'`，`follow_weekday` 为 null |
| `dayOverride.save` 新建 classday + `follow_weekday: 3` | 返回字段一致 |
| 同一 `date` 二次 save（不同 kind） | 该日期只剩一条，且为最新 kind |
| `kind: 'holiday'` 但传了 `follow_weekday: 3` | 落库后 `follow_weekday` 为 null |
| `date` 非法（`2026-1-1` / 空） | 抛 `invalid_date` |
| `kind` 非法（`'rest'`） | 抛 `invalid_kind` |
| `follow_weekday: 8` / `0` / `'3'` | 抛 `invalid_follow_weekday` |
| `name` 超长（> 30） | 抛 `invalid_name` |
| `dayOverride.delete({ id })` | `{ deleted: true }`，bootstrap 不再返回 |
| `dayOverride.delete({ date })` | 同上 |
| `bootstrap` | 返回体含 `dayOverrides` 键（数组） |
| `data.export` / `data.import` | export 含 `day_overrides`；import 不含该键的旧 payload 成功且其余表数据完整 |

**B. 解析层纯函数（约 14 项，内联 `resolveDayType` 逻辑）**

| 用例 | 断言 |
| --- | --- |
| 无 override + 无 holiday（周三） | `isHoliday = false`，`effectiveWeekday = 3`，`source = 'normal'` |
| 无 override + holiday 区间内 | `isHoliday = true`，`label` = 假期名，`source = 'holiday'` |
| override holiday 压在普通工作日 | `isHoliday = true`，`source = 'override'` |
| override holiday 压在 holiday 区间内 | 仍 `isHoliday = true`，`source = 'override'`（label 取标记名） |
| override classday 压在 holiday 区间内 | `isHoliday = false`，`source = 'override'` |
| override classday + `follow_weekday = 3`，真实日期为周六 | `effectiveWeekday = 3` |
| override classday + `follow_weekday = null`，真实日期为周六 | `effectiveWeekday = 6` |
| 周日（`getDay() = 0`）无 override | `effectiveWeekday = 7` |
| `courseOccursOn` 传 `effectiveWeekday = 3`，课程 `weekday = 3`，真实日期周六 | 命中 |
| 同上但课程 `weekday = 6` | 不命中 |
| 补课日周次：第 5 周周六 + `follow_weekday = 3`，课程 `week_rule = {ranges:[[5,5]]}` | 命中（周次取真实日期） |
| 同上，课程 `week_rule = {ranges:[[4,4]]}` | 不命中 |
| 单双周：`parity = 'odd'`，真实周次为偶数 | 不命中（不受 `follow_weekday` 影响） |
| **回归对照**：`overrides = []` 时，对同一批日期 `resolveDayType` 的 `isHoliday` 与旧 `holidayOn` 结果逐一相同，`effectiveWeekday` 与 `date.getDay()` 换算结果相同 | 全部相等 |

**C. 数据一致性（约 4 项）**

| 用例 | 断言 |
| --- | --- |
| 一天一条唯一性（连续 3 次 save 同 date） | bootstrap 中该 date 计数 = 1 |
| 跨学期日期也可标记（如寒假中的某天） | save 成功，不依赖 `semester_id` |
| 删除全部标记后 | `dayOverrides` 为空数组 |
| 标记不影响 `holidays` 表 | 标记前后 `holidays` 条数不变 |

## 7. 工作量与风险

- **工作量**：约 1 个工作日。迁移 0.5h、后端 1h、解析层 + 测试 2h、UI 2.5h、联动改造与验收 2h
- **风险 1｜`courseOccursOn` 改签名波及多处**：用**可选参数 + 缺省旧行为**，并加 6.2-B 的回归对照用例兜底
- **风险 2｜迁移与新函数部署顺序**：若先部署查询 `day_overrides` 的函数而表未建，线上 `bootstrap` 会直接失败 → 严格「先迁移并确认 `schema_version = 4`，再 `prepare_site(requiredSchemaVersion: 4)` 部署」；部署前用 `get_database` 复核
- **风险 3｜受限 DDL 约束**：不能用 `date` 类型 / DEFAULT / 唯一索引 / CHECK → 日期存 text、`id` 与 `created_at` 由 handler 生成、唯一性与取值校验放 handler（已由 6.2-A 覆盖）
- **风险 4｜旧备份导入**：`data.import` 对缺失 `day_overrides` 键必须容错，否则历史备份无法导入（6.2-A 最后一项专门覆盖）
- **风险 5｜周视图表头点击与移动端滚动 / 长按冲突**：表头区域小且无拖拽语义，用 `onClick` 即可；误触可在 Sheet 内取消，无破坏性写入
- **风险 6｜与「课表点击建待办」同时改 `SchedulePage.tsx`**：两功能都动 WeekView，**必须串行实施**，建议先做改动更小的「课表点击建待办」
