# 文件结构与调整方案

> 状态：**仅计划，未执行**。本文档对项目做一次完整清点，并给出符合现实软件开发工作模式的整理方案。

## 一、目标与原则

1. **三类分离**：把「开发过程文档」「原始数据来源」「可部署工程代码」三者清晰分开。
2. **贴合真实工程惯例**：根目录只保留可直接构建/部署的工程文件与标准配置；文档进 `docs/`，数据进 `data/`，一次性工具进 `scripts/tools/`。
3. **不破坏现有绑定**：Vite 与 Qoder Sites 对目录结构有硬约束，工程文件保持原位（详见「四、约束」）。
4. **只移动、不改名**：文档与数据文件保持原文件名，仅调整所在目录，降低认知与引用成本。
5. **可逆优先**：死代码先归档到 `_attic/` 而非直接删除，通过构建+全量测试验证后再决定删除。

## 三、清点中发现的问题（建议随整理一并修复）

1. **`README.md` 陈旧**：引用了并不存在的 `launch.bat` / `launch.ps1`，实际启动器是 `启动.bat` / `停止.bat`。→ 建议重写 README 与实际一致。
2. **`package.json` 脚本失效**：`dev:function` 指向 `dev/function-local.ts`（不存在），实际本地函数服务器是 `dev/local-server.mjs`。→ 建议修正或删除该脚本。
3. **死代码占用**：根级 `components/ui`（61 文件）+ `hooks/` + `lib/` 从未使用，徒增仓库体积与困惑。→ 建议归档后删除。
4. **验收报告分散**：三份验收报告分布在 `计划文档/` 与 `开发控制/` 两处。→ 统一到 `docs/acceptance/`。
5. **数据与文档混杂**：课表原始文件（xlsx/pdf/jpg/docx）与规划文档同放在 `计划文档/`。→ 拆出到 `data/raw/`。
6. **种子/备份散落根目录**：`seed-data.json`、`schedule-backup-*.json` 直接躺在根目录。→ 收进 `data/`。

## 四、约束（哪些文件绝对不能动，以及原因）

| 不可移动项 | 原因 |
| --- | --- |
| `index.html` `src/` | Vite 约定入口在根目录，`vite.config.ts` 未设 `root`，移动会破坏构建 |
| `functions/` | `prepare_site` 以 `functionDirectory="functions"` 绑定，移动会导致函数无法部署 |
| `dist/` | `prepare_site` 以 `webDirectory="dist"` 绑定 |
| `vite.config.ts` `tsconfig.json` `package.json` 等配置 | 工具链默认在根目录查找 |
| `.我的日程.qoder.site` | Sites 部署描述符，位置与项目根绑定，且为生成物不可手改 |
| `vendor/` | 被 `src/globals.css` 以相对路径 `../vendor/...` 引用，移动需同步改 CSS（不建议动） |

> 结论：本次整理**只动 D/E/F 三类**（死代码、文档、数据）以及 `scripts/` 内部的一次性工具，**不动 A/B/G**。

## 九、风险与回滚

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 误移动工程文件破坏 Vite/Sites 绑定 | 构建或部署失败 | 严格遵守「四、约束」，A/B/G 类不动 |
| 归档死代码其实被隐式引用 | 构建失败 | 阶段 4 设构建+测试验证点，失败即 `git mv` 还原 |
| 中文路径在某些工具下转义问题 | 移动脚本报错 | 全程用 `git mv` 并加引号；逐个移动 |
| `vendor/` 相对路径被牵连 | 样式丢失 | `vendor/` 与 `src/` 均不动，相对关系不变 |
| 一次性大提交难以回滚 | 定位困难 | 分阶段、分主题多次提交 |

**总回滚**：任一阶段出问题，`git mv` 反向还原或 `git checkout -- .` / `git reset` 回到阶段 0 的提交。
