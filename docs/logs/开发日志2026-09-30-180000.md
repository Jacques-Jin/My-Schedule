## 2. 技术架构

### 2.1 前端
- **React 19 + TypeScript + Vite**，SPA，哈希路由（`#/home` `#/schedule` `#/tasks` `#/homework` `#/campaigns` `#/settings`）
- 状态管理：**React Context + useReducer**（`src/store.tsx`），无第三方状态库
- 样式：自定义 CSS（`src/styles.css`）+ Tailwind 4 + shadcn vendor CSS（`vendor/`）
- 路由：手写 `getHashPage()`，无 react-router
- **不引入**：react-router、zustand/redux、UI 组件库（shadcn 脚手架已删除）、外部日期库（自写 `src/lib/date.ts`）

### 2.2 后端
- **Deno Edge Function**（`functions/index.ts` → `functions/adapter.mjs` → `functions/handler.mjs`）
- 底层 **Supabase**（Sites 托管），生产通过 adapter 注入 supabase 客户端
- 单个 `app` 函数，所有 API 通过 `?action=xxx` 路由
- 浏览器仅调用同源 `/functions/v1/app?action=...`

### 2.3 本地开发
- **`functions/local-dev-index.ts`**：内置假 Supabase（FakeBuilder），支持 select/insert/update/upsert/delete/eq/neq/in/is/gte/lte/order/limit/single/maybeSingle
- 本地与生产共用同一份 `handler.mjs`，行为一致
- `buildSeedTables()` 复刻 `seedIfEmpty` 的播种逻辑
- Vite dev server 端口 5173，API 代理到 8000
- **`dev/local-server.mjs`**：Node 版本地服务器（备用方案）

### 2.4 部署
- Qoder Sites：`prepare_site`（webDirectory=dist, functionDirectory=functions, spa=true, databaseAccess=read_write）→ `publish_site`
- 部署描述符：`.我的日程.qoder.site`（生成物，不可手改/移动）

## 4. 数据模型与数据库

### 4.1 数据库 Schema（当前 v4）

| 表名 | 主要字段 | 说明 |
|------|----------|------|
| `semesters` | id, name, start_monday, total_weeks, is_current | 学期 |
| `period_slots` | id, slot_no, start_time, end_time | 节次时间（14 节） |
| `holidays` | id, name, start_date, end_date | 校历节假日（支持区间） |
| `courses` | id, semester_id, name, teacher, weekday, start_period, end_period, week_rule, location, color, note | 课程，week_rule 为 JSON |
| `tasks` | id, title, date, start_time, end_time, category, priority, repeat_rule, reminder, done, campaign_id, note | 日程/待办 |
| `task_completions` | id, task_id, date | 重复日程的逐日完成记录 |
| `campaigns` | id, name, goal, deadline, color | 战役计划（日程分组容器） |
| `countdowns` | id, name, target_date | 自定义倒计时 |
| `homework` | id, title, course_id, due_date, description, completed | 作业 |
| `day_overrides` | id, date, kind, follow_weekday, name | 调休标记（v4 新增） |
| `settings` | id, remind_minutes, overlay_repeat | 用户偏好 |

### 4.2 week_rule 格式
JSON 字符串：`{"ranges":[[lo,hi],...],"parity":null|"odd"|"even"}`
- `ranges`：周次区间列表，如 `[[1,17]]` 表示第 1-17 周
- `parity`：单双周过滤，null 表示不过滤

### 4.3 调休解析优先级
`resolveDayType(dateStr, holidays, overrides)` 返回 `DayType`：
1. **override(holiday)** → 最高优先，强制放假
2. **override(classday)** → 强制上课，`follow_weekday` 决定按周几课表
3. **holiday range** → 校历假期区间
4. **normal** → 正常日期

### 4.4 SEED 数据
定义在 `functions/handler.mjs`（`export const SEED`），`seedIfEmpty()` 仅在库为空时播种。SEED 包含 2026 秋季学期完整数据（25 门课程、节假日、节次时间、作息日程）。

## 11. 关键设计决策与注意事项

### 11.1 状态管理
- `store.tsx` 的 `bootstrap` reducer 会**整体替换 state**（`return { ...action.data, status: "ready" }`）
- 如果 bootstrap 响应缺少某个字段（如 `dayOverrides`），该字段变为 `undefined`，后续 `.filter()` / `.find()` 会崩溃导致白屏
- **新增数据表时必须同步更新**：handler.mjs 的 bootstrap 返回、store.tsx 的 State 接口、local-dev-index.ts 的 FakeBuilder

### 11.2 SEED 是唯一数据真相
- 定义在 `functions/handler.mjs`（`export const SEED`）
- `seedIfEmpty()` 只在库为空时播种
- 本地与生产共用同一份 SEED
- 修改 SEED 后，生产需通过 `data.import` 或手动重播种同步

### 11.3 周次/日期引擎
- `src/lib/date.ts` 是核心计算层
- `weekIndexOf(date, semester)` → 当前周次
- `courseOccursOn(course, date, semester)` → 课程是否在当天
- `resolveDayType(dateStr, holidays, overrides)` → 调休解析
- `expandTaskOn(task, date, completions)` → 重复日程展开

### 11.4 本地开发 vs 生产
- 本地用 `functions/local-dev-index.ts`（内存假 Supabase）
- 生产用 `functions/index.ts` + `adapter.mjs`（真 Supabase）
- 两者共用 `handler.mjs`，行为一致
- **本地数据重启即重置**，生产数据持久化

### 11.5 文件结构硬约束
- `src/` `functions/` `dist/` `vendor/` `index.html` 及配置文件**绝不移动**
- Vite 约定入口在根目录，`vite.config.ts` 未设 `root`
- `prepare_site` 以 `functionDirectory="functions"` 和 `webDirectory="dist"` 绑定
- `vendor/` 被 `src/globals.css` 以相对路径 `../vendor/...` 引用
