## 2. 技术架构

### 2.1 前端栈

- React 19.2 + Vite 8 + TypeScript（`tsc --noEmit` 为类型检查入口）
- 样式：手写 `src/styles.css`（Liquid Glass Design System v2.0，2239 行）为主视觉系统；
  `src/globals.css` 为 Tailwind 4 + shadcn vendor token 层（仅少量工具类实际使用）
- toast：`sonner`；IndexedDB 封装：`idb`
- 路由：hash 路由（`window.location.hash`，`#/home` 等），无路由库
- 6 个页面：`src/pages/` — HomePage / SchedulePage / TasksPage / HomeworkPage / CampaignsPage / SettingsPage

### 2.2 数据层（离线优先）

- `src/lib/db.ts`：IndexedDB wrapper（本地缓存 + 同步队列两张存储）
- `src/lib/sync.ts`：write-behind 同步管理器
  - 所有写操作先入队 IndexedDB，`syncNow()` 冲刷队列
  - 失败重试，`attempts >= 5` 丢弃该队列项（防死锁；副作用：长期离线期间的写入可能丢失，见 §6）
  - 网络监听：Web 用 `online/offline` 事件；原生用 Capacitor Network 插件
- `src/store.tsx`：全局唯一数据入口，所有读写经此；UI 不直接碰 db/api
- `src/lib/api.ts`：`requestJson(action, payload?)` 单一 RPC 入口
  - Web：同源 `fetch("/functions/v1/app?action=...")`
  - 原生：`CapacitorHttp.request` 直连 + 显式 `Origin: SITE_ORIGIN` 头（v55 修复核心）
- `src/lib/config.ts`：`SITE_ORIGIN` 常量 + `API_BASE` 平台分支

### 2.3 后端

- Qoder Sites Functions（Deno runtime），单入口 `?action=` 分发
- 数据库 schema v4；网关强制校验 `/functions` 请求的 Origin 必须等于站点域
  （**硬约束**：任何原生/第三方客户端必须显式带 `Origin: https://my-schedule-akzzfsdx3vh.qoder.zone`）

### 2.4 Android（Capacitor 8）

- `capacitor.config.ts`：appId `com.jack.myschedule`，webDir `dist`，`CapacitorHttp.enabled: true`，
  启动屏/背景色 `#0a0a0f`（深色，避免白闪）
- debug 与 release 签名不同 → 换装必须先 `adb uninstall`（会清空本地 IndexedDB，云端数据重新 bootstrap）
- `src/themes/loader.ts` 在原生端联动 `@capacitor/status-bar`：
  深色主题（dark-glass / paper-terminal）→ `Style.Dark`，其余 → `Style.Light`
- release APK：`android/app/build/outputs/apk/release/app-release.apk`

## 3. 本版本关键事件：原生同步 403 修复（v55）

摘要（详见 `开发日志2026-10-02-185200.md`）：

- 现象：App 同步红点常驻、toast 反复"数据同步失败"
- 根因：Sites 网关要求 Origin 等于站点域；Capacitor 的 fetch patch 用 `new Request()` 构造请求，
  `Origin` 属 forbidden header 被静默剥离 → 原生请求无 Origin → 403
- 修复：原生分支改走 `CapacitorHttp.request`（原生层逐条 `setRequestProperty`，无 forbidden 过滤），
  显式附 `Origin: SITE_ORIGIN`；Web 分支不变
- 验证：真机重装后 bootstrap 与积压队列全部 200，红点消失；release APK 已包含此修复并装机验证

## 4. UI 设计体系（UI 设计 Agent 必读）

### 4.1 设计语言总纲

默认主题 **Liquid Glass**：macOS 液态玻璃风格。

- 半透明白玻璃卡片（`rgba(255,255,255,0.45)`）+ `backdrop-filter: blur(24–40px) saturate(180%)`
- 环境光背景：`body::before` 固定层，4 团 radial-gradient 彩色光斑（紫/橙/绿/蓝），`z-index:-1`
- 玻璃高光：`inset 0 1px 0 rgba(255,255,255,0.65)` 顶边内发光模拟折射
- 圆角大（16–24px）、阴影软、动效弹簧曲线
- 移动端优先：底部导航（64px）+ 底部抽屉 Sheet；桌面端顶部导航（56px，`max-width:960px` 居中）

### 4.2 主题机制（新增/修改主题的正规流程）

| 文件 | 职责 |
|------|------|
| `src/themes/registry.ts` | 主题清单 `THEMES[]`（id / name / description / cssFile） |
| `src/themes/loader.ts` | `applyTheme(id)`：设置 `<html data-theme="id">` + 动态注入 `<link href="/themes/xxx.css">` + 写 localStorage `app-theme` + 原生状态栏联动 |
| `src/themes/*.css` | 各主题覆盖文件，全部以 `[data-theme="id"]` 选择器作用域隔离 |
| `src/pages/SettingsPage.tsx` | 设置页「外观主题」卡片网格（`AppearanceSection` / `ThemeCard`），切换即生效并经 `saveSettings({theme})` 云同步 |

**新增主题步骤**：registry 加一条 → 新建 `[data-theme="新id"]` 覆盖 css → 完成。
基础 `styles.css` 不应为新主题改动；主题只覆盖 token 与必要选择器。
默认主题 `cssFile: ""`（即 styles.css 本体）。

### 4.5 四套主题设计要点

1. **Liquid Glass（default）** — 见 §4.1。浅色、白玻璃、彩色环境光斑。
2. **Dark Glass**（`dark-glass.css`，800 行）— 深色液态玻璃。
   - 底 `#10101c`，玻璃 `rgba(21,21,36,0.72)`，primary `#8B9CF0`（实底按钮 `#4E5FE6`）
   - 环境光晕改为画在 `body` 上的高饱和 radial-gradient（紫/蓝/粉/天蓝 5 团），
     并停用 `body::before`（其 `z-index:-1` 会被不透明 body 背景遮挡）
   - 用户偏好（务必遵守）：深色要**鲜艳光晕、文字可读、饱和不惨白、hover 高亮**，拒绝近黑无光
3. **Neo Brutalism**（`neo-brutalism.css`，2204 行）— 新粗野主义。
   - 纯白平底 + 纯黑实边 + `4px 4px 0 #000` 硬偏移阴影；blur/shadow/highlight 全部归零
   - 高饱和撞色：primary #0055ff / warning #ffcc00 / danger #ff0033 / bg #fffef5
4. **Paper Terminal**（`paper-terminal.css`，1085 行）— 点阵仪器风（Teenage Engineering / 老示波器）。
   - 4 色极克制 palette：奶油纸 #eae5d8 / 暖黑墨 #1f1d1a / 唯一强调 navy #2e3a8c / 辅助灰 #8a8578
   - 字体分层：DotGothic16（display）/ JetBrains Mono（mono）/ Inter+Noto Sans SC（body）
   - 完全去玻璃：blur 0、shadow none、平纸面
   - 因组件 inline 色不受 token 控制，该主题大量使用 `!important` 覆盖（已知债，见 §4.6）

### 4.6 已知 UI 约束与设计债（后续 Agent 注意）

1. **双 token 体系并存**：`globals.css`（Tailwind/shadcn `--background` 等）与 `styles.css`（`--color-*`/`--glass-*`）。
   `globals.css` 的 `body { color: var(--foreground) }` 优先级高于主题 token，
   深色主题必须写 `[data-theme="x"] body { color: ... }` 更高优先级覆盖，否则继承文字近黑不可读。
2. **inline style 颜色**：课程/分类色由 `colors.ts` 经 inline style 注入，主题无法用 token 覆盖，
   只能 `!important`（paper-terminal 已如此）。新设计尽量把颜色移入 CSS 变量可解此债。
3. **不跟随系统深色**：v49 已移除 `prefers-color-scheme` 媒体查询，主题仅手动切换（设置页）。
   验收须覆盖"跟随系统深色"与"不跟随"两类浏览器（用户环境：PC Edge 开系统深色 + 手机夸克）。
4. **emoji 导航图标**：跨平台渲染不一致（Windows/Android/iOS 字形不同），是已知债；
   若做图标升级，建议 SVG sprite 或图标字体，保持 6  tab 结构不变。
5. **DotGothic16 无简体字形**：paper-terminal 的中文会回退系统字体，display 字体仅对数字/拉丁生效。
6. **主题卡无预览图**：`ThemeInfo.preview` 字段预留但未使用，设置页卡片仅文字描述。
7. **安全区**：底部导航未做 `env(safe-area-inset-bottom)` 适配验证（全面屏手势条遮挡未实测）。
8. **横屏**：未做专门适配，未验收。
