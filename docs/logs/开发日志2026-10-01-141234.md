# 开发日志 2026-10-01 #5

## 修复：跨端数据不同步 + 操作无同步提示

### 问题

1. 电脑端添加的作业，手机端看不到；甚至 Edge 打开的网页看不到夸克布置的作业。
2. 进行操作后不再出现"数据同步成功"弹窗提示，右上角也不再显示待同步数量。

### 根因

**跨端不同步**（一条完整的失败链）：

- `functions/handler.mjs` 所有 `save` 分支为 `if (payload.id) update else insert`。
- 客户端离线优先生成本地 UUID，首次写入时服务端并不存在该 id，`update` 命中 0 行 → `.single()` 报错 → 503。
- 旧版 `sync.ts` 捕获错误后**静默丢弃**队列项，数据永远只留在本地 IndexedDB，从未真正上云 → 换设备/换浏览器即丢失。

**无提示**：

- 在线时 store 的各 `save/delete/complete` 直接 `await api.X()`，仅在失败时入队；成功路径**完全不经过同步状态机**，因此 `syncing→synced` 跃迁不发生，SyncIndicator 的成功 toast 从不触发。
- 右上角待同步徽标只在队列非空时显示；在线直写使队列恒空，徽标恒不出现（叠加此前 503 静默丢弃，用户彻底失去反馈）。

### 修复

| 文件 | 改动 |
|------|------|
| `functions/handler.mjs` | 新增 `upsertById()`：先按 id `update`，命中 0 行则以客户端 id `insert`。semester/holiday/course/task/campaign/countdown/dayOverride/homework 全部改用 upsert 语义 |
| `src/lib/sync.ts` | 错误分支不再静默丢弃：`attempts<5` 保留队列项并 30s 后重试，达上限才移除；新增 `notifyDirectSync()` 供在线直写发出 `syncing→synced` 脉冲 |
| `src/lib/db.ts` | 新增 `updateSyncItem()`、`getMeta()`/`setMeta()`（`_sync_meta`） |
| `src/store.tsx` | `refresh()` 改为"服务端为基 + 本地独有条目（created_at 晚于 lastBootstrap）保留并回推"的合并逻辑；新增 `adoptSaved()` 采纳服务端返回行的 id，避免本地/云端 id 分叉；25 处在线直写成功分支全部追加 `sync.notifyDirectSync()` |
| `src/components/SyncIndicator.tsx` | 直写成功 toast 复用固定 id `sync-direct`，使连续操作的多条成功提示合并为一条，避免堆叠 |

### 验收（线上 runtime v53）

- **跨端可见**：`bootstrap` 返回的作业在 UI 全部渲染；经 API 从"另一端"写入的行在本端刷新后可见。
- **upsert 语义**：同 id 二次保存返回单行、无重复；服务端作业计数正确。
- **写入上云**：通过应用表单新增作业 → `bootstrap` 立即包含该行（已持久化到云端）。
- **同步提示**：新增作业后弹出"数据同步成功"toast（此前缺失，已恢复）。
- **状态机健康**：SyncIndicator 处于 synced / 0 待同步，无卡死的错误态。
