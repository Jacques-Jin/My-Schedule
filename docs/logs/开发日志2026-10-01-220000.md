### 1.2 解决方案

```

```

### 2.2 修改文件

**`src/store.tsx`** — 缓存优先 + 写穿同步

Bootstrap 流程：
1. 先读 IndexedDB → 有数据则立即渲染（毫秒级）
2. 再调 API → 成功后更新 IndexedDB + 刷新 UI
3. API 失败但有缓存 → 保持缓存数据
4. API 失败且无缓存 → 显示错误

写操作：API 成功后同步写入 IndexedDB（write-through）

## 3. Phase 2：同步队列 + 离线写入（v42）

### 3.1 新增文件

**`src/lib/sync.ts`** — Write-behind 同步管理器

- `enqueue(action, payload)` — 写操作入队

- `scheduleSync()` — 2 秒防抖调度
- `initSync()` — 监听 online/offline 事件
- `onSyncChange()` — 状态变更订阅

**`src/components/SyncIndicator.tsx`** — 同步状态指示器

- 显示状态：同步中… / 离线 / 待同步数量
- 点击手动触发同步
- 同步完成自动隐藏

### 3.2 同步流程

```
写操作 → IndexedDB（立即生效）→ 加入同步队列 → 2秒后推送 API → 成功后出队
                                              ↓
                                     离线？保留队列，联网后重试
```

### 3.3 冲突策略

- LWW（Last Write Wins）：以时间戳最新为准
- 同步队列按入队顺序依次推送

### 4.4 关键 Bug 修复：snake_case / camelCase 映射

**问题**：IndexedDB stores 使用 snake_case（`day_overrides`），State 接口使用 camelCase（`dayOverrides`）。`loadFromCache()` 返回 snake_case 键名导致 `state.dayOverrides` 为 undefined，应用崩溃。

**修复**：

```typescript
const STORE_KEY_MAP: Record<string, string> = {
  period_slots: "periodSlots",
  task_completions: "completions",
  day_overrides: "dayOverrides",
};

const REVERSE_KEY_MAP: Record<string, string> = {
  periodSlots: "period_slots",
  completions: "task_completions",
  dayOverrides: "day_overrides",
};
```

- `loadFromCache()` 返回 camelCase 键名
- `cacheBootstrap()` 和 `importAllData()` 处理 camelCase → snake_case 映射

## 7. 架构决策

### 7.1 为什么保留 API 调用？

IndexedDB 作为缓存层，API 仍为权威数据源：
- 保证多设备数据一致性
- 保留 Supabase 云端备份
- 不改变后端架构，最小化改动

### 7.2 为什么用 `idb` 库？

- Promise-based API，与 async/await 天然配合
- TypeScript 类型安全
- 自动处理 transaction 完成确认
- 体积极小（~1KB gzip）

### 7.3 为什么延迟同步（2 秒）？

- 合并短时间内的多次写操作
- 减少 API 调用频率
- 用户操作零延迟感知
