## 3. 技术架构与关键约束

- **前端**：React 19 + TypeScript + Vite，SPA，hash 路由；状态用 React Context + useReducer（`src/store.tsx`）。
- **后端**：Deno Edge Function（`functions/index.ts` → `functions/adapter.mjs` → `functions/handler.mjs`），底层 Supabase；生产已启用 database + functions。
- **本地开发的关键技巧**：生产 `adapter.mjs` 依赖 `x-instance-id` 头和 `SUPABASE_*` 环境变量，本地无法直接跑。为此新建了 **`functions/local-dev-index.ts`**：内置一个假的内存版 Supabase（FakeBuilder，thenable，支持 select/insert/update/upsert/delete/eq/neq/in/is/gte/lte/order/limit/single/maybeSingle），并 `import { handleRequest, SEED } from "./handler.mjs"`，用 `buildSeedTables()` 复刻 `seedIfEmpty` 的播种逻辑（semester id=1；courses 挂 `semester_id:1`；tasks 挂 `campaign_id:null`；settings id=1）。**本地与生产共用同一份权威 SEED**，行为一致。
- **SEED 是唯一数据真相**：定义在 `functions/handler.mjs`（已 `export const SEED`）。`seedIfEmpty()` 只在库为空时播种，并建立 courses.semester_id / tasks.campaign_id 关联。
- **周次/日期引擎**：`src/lib/date.ts` 的 `weekIndexOf`、`courseOccursOn`、`expandTaskOn`、`holidayOn`；`week_rule` 为 JSON：`{"ranges":[[lo,hi],...],"parity":null}`。
- **部署绑定**：项目根的 **`.我的日程.qoder.site`** 描述文件绑定了 projectId/siteId/deploymentId/releaseId；`webDirectory=dist`。**移动工程文件或该描述文件会破坏 Vite 构建与 Sites 绑定，禁止移动。**
- **目录已整理**：工程文件全部留在根目录；计划类文件已移入 `计划文档/`（含 PRD.md、开发计划.md、parsed_schedules.txt、课表集/、用户笔记/）。
- **环境坑（重要）**：node/npm/deno **不在 PATH**；PowerShell 5.1 + gb2312 控制台，`.ps1` 必须纯 ASCII，`taskkill /F` 因编码失败需改用 `Stop-Process -Id X -Force`；Git Bash 里没有 `timeout /t`，用 `sleep`。
