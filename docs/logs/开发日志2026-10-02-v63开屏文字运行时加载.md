# 开发日志 2026-10-02 · v63 开屏文字运行时加载 + 编辑器入包

## 需求

用户要把「开屏文字编辑器」放进本地独立版包，用于在同学电脑上整活。
障碍：v62 的开屏文字是**构建时** `import splashText from "../splash-text.json"`
烤进 JS bundle 的，包内改 JSON 不会生效。

## 变更（Runtime v63）

1. **开屏文字改为运行时加载**
   - 配置移至 `public/splash-text.json`（随构建进 dist 根 / 包内 `app/`）。
   - `SplashScreen.tsx`：mount 时 `fetch("/splash-text.json", { cache: "no-store" })`，
     校验后 setState；任何失败回退内置默认 `我的日程 / My Schedule`。
     fetch 远早于标题淡入节拍（settling ≥1.55s）完成，无可见切换。
   - 删除 `src/splash-text.json` 与构建时 import。
   - 效果：开发版 / 本地独立版 / 线上站点**保存后刷新即生效，无需重新构建**；
     APK 资源只读除外。

2. **编辑器重写为 Deno 原生**（`scripts/splash-text-editor.mjs`）
   - 原 node:http 版本在包内 Deno 的 node 兼容层下异常（进程存活但不监听端口），
     改为 `Deno.serve` 单实现，开发版与本地版共用。
   - 环境变量覆盖：`SPLASH_EDITOR_PORT`、`SPLASH_TEXT_CONFIG`（包内 bat 用）。
   - 权限标志必须含 `--allow-env`（缺它会 NotCapable 直接崩，表现为"端口不监听"）。
   - `set-splash-text.bat` 从 node 切换到 Deno，加 5299 占用守卫。

3. **本地独立版包纳入编辑器**
   - 包内新增 `开屏文字编辑.bat`（端口 5399，写包内 `app/splash-text.json`）
     与 `server/splash-text-editor.mjs`；README.txt 增「整活专用」章节。
   - 文字随文件夹拷贝/发送：同学电脑上开屏即显示改过的标题。
   - 重新打包：`output/MySchedule-Local/` + `我的日程-本地版-v63.zip`（~48MB）。

## 验证记录

- 包内编辑器（5399）浏览器保存「奶龙的大宝贝」→ `app/splash-text.json` 更新、
  服务器返回新内容、应用页内 `fetch('/splash-text.json')` 探针返回新标题；
  「重置为默认」恢复 `我的日程 / My Schedule`。
- 开发版编辑器（5299）curl 保存 DEVTEST → `public/splash-text.json` 更新；reset 恢复。
- 开屏画面截图因工具往返延迟（>4s）抓不住标题节拍，改用 fetch/DOM 探针确认
  （已知 splash 验证时序问题，见记忆 splash-verification-gotchas）。
- tsc --noEmit 通过；v63 构建产物入包。

## 坑记录

- 用户早前自行启动的**旧 node 编辑器进程**一直存活占用 5299，导致新 bat 的
  占用守卫只开浏览器、curl 打到了旧进程（写已删除的 src 路径并重建了文件）。
  杀旧进程 + 删残留文件后复测通过。教训：换实现前先确认端口上跑的是谁。
- `output/` 目录被存活进程（deno/文件预览）锁定时 rmSync 报 EBUSY：先杀自家
  测试进程再打包。

## 影响面

- 应用行为变更 → Runtime v63；线上站点与 APK 仍为 v62 产物（默认文字不变），
  如需线上/APP 同步 v63 需另行部署/打包。
