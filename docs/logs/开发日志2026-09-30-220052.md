## 1. 问题现象

战役详情中勾选**重复类**子计划（如每日重复的「起床早餐」）时：

- 勾选框点击后**不显示选中**；
- 每点一次就向 `task_completions` **插入一条重复记录**（同一 task_id + date 出现多行）；
- 战役进度条对重复任务**永不变动**。

非重复任务不受影响。

---

## 2. 根因分析

`CampaignsPage.tsx` 对完成态的判定与写入用了错误的字段：

```tsx
// 修复前
const handleToggle = (task) => completeTask({ id: task.id, date: task.date, done: !task.done });
<TaskItem done={task.done} ... />
const done = campaignTasks.filter(t => t.done).length;   // 进度
```

而重复任务的完成态**不存放在 `task.done` 列**（该列恒为 `false`），而是按日期存放在 `task_completions` 表（见 `handler.mjs` `task.complete` 与 `store.tsx` `completeTask`）。因此：

1. `done` prop 恒为 `false` → 勾选框永不显示选中；
2. `done: !task.done` 恒为 `true` → 每次点击都走 insert 分支 → 重复记录累积；
3. 进度按 `t.done` 统计 → 重复任务永远不计入 done。

对照 `TasksPage.tsx` 的正确用法：重复任务须以「某日期是否有 completion 记录」判定完成态，且写入的 `done` 取该判定的反值。

---

## 3. 修复方案

在 `CampaignsPage.tsx` 引入与 TasksPage 同语义的判定函数，并统一三处使用点。战役详情每行代表该任务在其 `task.date` 那天的实例（列表按 `task.date` 分组），故判定/写入均以 `task.date` 为日期键：

```tsx
const isTaskDoneOn = useCallback((task: Task, date: string): boolean => {
  const rule = JSON.parse(task.repeat_rule || '{"type":"none"}');
  if (rule.type !== "none") {
    return state.completions.some(c => c.task_id === task.id && c.date === date);
  }
  return task.done;
}, [state.completions]);

const handleToggle = useCallback((task: Task) => {
  completeTask({ id: task.id, date: task.date, done: !isTaskDoneOn(task, task.date) });
}, [completeTask, isTaskDoneOn]);
```

统一使用点：

| 位置 | 修复前 | 修复后 |
|------|--------|--------|
| `TaskItem` 的 `done` prop | `task.done` | `isTaskDoneOn(task, task.date)` |
| `handleToggle` 的 `done` 入参 | `!task.done` | `!isTaskDoneOn(task, task.date)` |
| 详情页 `campaignProgress` | `filter(t => t.done)` | `filter(t => isTaskDoneOn(t, t.date))` |
| 列表页卡片进度 | `filter(t => t.done)` | `filter(t => isTaskDoneOn(t, t.date))` |

`campaignProgress` 的 useMemo 依赖补入 `isTaskDoneOn`（其内含 `state.completions`），保证勾选后进度即时重算。
