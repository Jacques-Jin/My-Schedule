## 发现的问题

### 1. 用户报告的数据丢失问题

**现象**：关闭网页后修改不保存

**根因分析**：
- **线上环境（production）**：使用 Supabase，数据持久化正常工作。测试确认：3 条默认任务在页面刷新后仍然存在。
- **本地开发环境（local dev）**：使用 `functions/local-dev-index.ts` 中的内存 FakeBuilder，服务器重启后数据丢失。

**结论**：用户报告的问题发生在本地开发环境，非线上问题。PRD 中的 Hybrid Offline-First 方案仍然有价值，但优先级调整为：先确保本地开发体验，再考虑离线同步。

### 2. v41 部署后线上 503 错误

**现象**：部署 v41 后，线上站点显示"连接服务失败"，bootstrap API 返回 503。

**根因**：
- `handler.mjs` 的 bootstrap action 查询 settings 表时包含 `theme` 列：
  ```javascript
  ["settings", "id,remind_minutes,overlay_repeat,theme"]
  ```
- 但数据库 schema v4 的 settings 表只有 3 列：`id, remind_minutes, overlay_repeat`
- `theme` 列从未通过 migration 添加到数据库
- v30-v41 的主题切换功能在客户端使用 localStorage 存储主题偏好（v41 修改），但 handler 代码仍尝试从数据库查询 theme 列

**修复**：
1. `handler.mjs` 第 171 行：bootstrap 查询移除 `theme` 列
   ```javascript
   ["settings", "id,remind_minutes,overlay_repeat"]
   ```
2. `handler.mjs` 第 487 行：settings.save action 移除 `theme` 字段
   ```javascript
   const fields = ["remind_minutes", "overlay_repeat"];
   ```
3. 代码已有容错逻辑（第 180 行）：如果 theme 为 undefined，默认设为 "default"

**为什么不用 database migration**：
- 尝试创建 migration 添加 theme 列，但 restricted DDL 拒绝（unsupported_ddl）
- 由于 v41 已将主题存储改为 localStorage，数据库不需要 theme 列
- 修复 handler 代码是更简单、更正确的方案
