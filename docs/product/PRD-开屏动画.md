## 1. 背景与目标

### 1.1 背景
- 应用当前无品牌化开屏体验：Web 端首屏直接渲染；Android 端仅有 Capacitor 原生静态启动屏（`#0a0a0f` 底 + 图标，2s）。
- v55 已确立 Liquid Glass 设计语言与 4 套主题，但缺少一个「启动瞬间」的品牌锚点。

### 1.2 目标
- 设计**一个统一概念**的开屏动画，做**两个变体**分别适配桌面端与手机端。
- 传递三种气质：**高级感**（克制、精致缓动、留白）、**高效感**（利落、有速度暗示）、**品牌感**（与 Liquid Glass 液态玻璃语言一致）。
- 允许**少量色彩变化**，但不得喧宾夺主。
- 不劣化性能基线（冷启动 < 2s）。

### 1.3 非目标（本期不做）
- 不做可跳过广告页 / 运营位。
- 不改造 emoji 导航图标（属另一条设计债）。
- 不为开屏动画单独制作视频/位图资源。

## 2. 设计概念：「光迹 · Trace」

### 2.1 隐喻
> 一天从一道光弧开始——它扫过时间，落定为你的日程。

一道发丝级光弧顺时针绘制（时间/日程的抽象），收尾时「落定」并补合缺口，象征「今天已就绪」。整个过程短、准、稳，暗示高效。

### 2.2 情绪板关键词
克制 · 精密 · 液态玻璃 · 单一光源 · 弹簧落定 · 穿透式转场 · 大留白

### 2.3 为什么合理且有创意
- **合理**：图形语义与「日程/时间」强相关；动作语言（绘制→落定→补合→穿透退出）符合用户对产品「就绪」的心理预期；全部复用现有缓动与色彩 token，风格统一。
- **创意**：缺口光弧 + 拖尾辉光赋予「加载即品牌」的双重身份（既是启动动画也是首帧 loading 反馈）；字距由宽收窄的揭示手法与玻璃高光横扫，是高端产品常见的精致细节，但在此项目属首次引入。

## 3. 视觉规格

### 3.1 图形元素

| 元素 | 规格 |
|------|------|
| 光弧（主 mark） | SVG `<circle>` 用 `stroke-dasharray/dashoffset` 绘制。半径：桌面 60px、手机 44px。线宽 2.5px（发丝级但可见）。端点 `stroke-linecap: round`。 |
| 弧渐变 | 沿弧方向的线性/锥形渐变，起色 `var(--color-primary)`（Liquid Glass 为 `#5856d6`），止色偏蓝（约 primary 色相 -15°，或直接用 `#4E5FE6` 一类）。仅这一处彩色。 |
| 尖端辉光 | 弧线绘制端叠加一个小半径 radial 光点 + `filter: drop-shadow`，深色主题下更明显（辉光而非实色块，遵循用户深色偏好：鲜艳光晕、不惨白）。 |
| 缺口 | 光弧绘制到约 300°（留 60° 缺口），随后阶段补合。 |
| 字标 | 文本「我的日程」。字重 600。字号：桌面 26px、手机 20px。颜色 `var(--color-text)`。字距动画：初始 `0.35em` → 收至 `0.02em`。 |
| 高光横扫 | 一道窄斜向白色渐变条（`rgba(255,255,255,0→0.55→0)`）在字标上横扫一次，模拟玻璃折射（呼应 `--glass-highlight`）。仅浅色主题可见；深色主题改为一次极淡的 primary 光晕呼吸。 |

### 3.2 颜色（严格取 token，不得硬编码新色）
- 主色：`--color-primary` / `--color-primary-light`
- 文本：`--color-text` / `--color-text-secondary`
- 背景：`--color-bg`（Liquid Glass `#f0f0f5`）或对应主题底色
- 环境光斑：复用 `body::before` 的 4 团 radial-gradient（紫/橙/绿/蓝），开屏层可低透明度复用一份作为氛围底，**不得**新增色相。
- Android 接力底色：`#0a0a0f`（与原生启动屏一致，防白闪）。

### 3.3 布局（双端）

**桌面端（`min-width: 768px`）**
- 水平居中构图，图形与字标**横向并排**：光弧在左，字标在右，间距 28px，整体垂直居中。
- 大量留白；容器 `max-width` 不限，居中即可。
- 底部可选一行极淡副标题「My Schedule」（`--color-text-secondary`，字号 12px，字距 0.2em），仅桌面显示。

**手机端（`max-width: 767px`）**
- **纵向堆叠**：光弧在上，字标在下，间距 20px，整体居中。
- 顶部留状态栏高度、底部留 `env(safe-area-inset-bottom)`，避免手势条/刘海遮挡。
- 不显示副标题（保持极简）。

## 4. 动画规格（时间轴）

> 缓动统一使用现有 token：常规 `--ease: cubic-bezier(0.4,0,0.2,1)`；落定/回弹 `--ease-spring: cubic-bezier(0.34,1.56,0.64,1)`。

### 4.1 桌面端时间轴（总时长 ≈ 4.2s，含静场与停顿）

| 阶段 | 时间 | 动作 | 缓动 |
|------|------|------|------|
| A 静场 | 0–700ms | 仅环境光斑淡入的空白静场，让动画从容起势 | ease |
| B 绘制 | 700–1800ms | 光弧 `stroke-dashoffset` 从满到 300°（顺时针）；尖端辉光跟随 | ease |
| C 落定 | 1800–2200ms | 整体 scale 0.98→1.0 弹簧脉冲；字标淡入上浮 + 字距 0.35em→0.02em | ease-spring |
| D 高光 | 2200–2600ms | 玻璃高光横扫字标一次 | ease |
| E 停顿 | 2600–3200ms | **poise**：字标已排定、圆环缺口仍开，静止停留供视觉反应 | — |
| F 补合 | 3200–3650ms | 缺口 60° 平滑补合为完整环 | ease |
| G 停留 | 3650–3850ms | 完整环静止保持 | — |
| H 退场 | 3850–4200ms | 分层退场：字标上浮淡出、环微放大、整层（含底色）0.6s 交叉淡出露出首页 | ease |

### 4.2 手机端时间轴（总时长 ≈ 3.7s）

| 阶段 | 时间 | 动作 | 缓动 |
|------|------|------|------|
| A 静场 | 0–600ms | 空白静场 | ease |
| B 绘制 | 600–1550ms | 光弧绘制到 300°，尖端辉光跟随 | ease |
| C 落定 | 1550–1900ms | scale 脉冲；字标淡入上浮 + 字距收窄 | ease-spring |
| D 高光 | 1900–2250ms | 高光横扫一次 | ease |
| E 停顿 | 2250–2750ms | **poise** 停留 | — |
| F 补合 | 2750–3150ms | 缺口补合 | ease |
| G 停留 | 3150–3350ms | 完整环保持 | — |
| H 退场 | 3350–3700ms | 分层交叉淡出退场 | ease |

### 4.3 时序约束
- 最短展示时长：桌面 2800ms、手机 2400ms（即使数据已 ready 也不提前硬切）。
- 最长展示时长（硬上限）：5000ms，超时无论数据是否 ready 强制退场。
- 退场为 0.6s 交叉淡出（整层含底色一同淡出），**不得**硬切。
- 退场后组件卸载，不得残留 DOM 或监听器。

## 5. 主题适配

- 开屏层根节点在挂载**前**读取 `getStoredTheme()`（`src/themes/loader.ts`），写入 `data-theme` 属性，使 CSS 变量正确级联；未设置时回退 Liquid Glass（默认）。
- 四套主题下的差异：

| 主题 | 底色 | 弧/辉光 | 高光手法 |
|------|------|---------|----------|
| Liquid Glass | `#f0f0f5` + 环境光斑 | primary 渐变弧 + 柔辉光 | 白色玻璃高光横扫 |
| Dark Glass | `#10101c` | primary `#8B9CF0`，**辉光增强**（鲜艳不惨白） | 淡 primary 光晕呼吸 |
| Neo Brutalism | `#fffef5` | 纯黑描边（无渐变、无辉光），硬边 | 改为一次性硬切显影（无柔光），保持粗野克制 |
| Paper Terminal | `#eae5d8` | navy `#2e3a8c` 单色弧，无辉光 | DotGothic16 逐点显影（点阵感），禁用柔光 |

- 主题差异通过 `[data-theme="x"] .splash-*` 选择器覆盖实现，**不改基础 `styles.css`**（遵循 v55 §4.2 主题机制）。

## 6. 无障碍与降级

- **`prefers-reduced-motion: reduce`**：跳过所有运动，直接显示静态终态（完整环 + 字标），停留 600ms 后淡出。
- 动画期间容器 `aria-hidden="true"` + `role="presentation"`，不进入无障碍树；提供 `aria-busy` 语义于加载态。
- 所有动画仅用 `opacity` / `transform` / `stroke-dashoffset`（GPU 友好），避免触发 layout/paint 抖动。
- 用户点击/触摸开屏层（手机端）或按任意键（桌面端）可**立即跳过**至终态并退出（尊重高效预期）。

## 7. 平台集成

### 7.1 Web
- 在 `src/App.tsx` 应用启动流程中挂载 `<SplashScreen />`：组件在首屏渲染前显示，内部同时等待「动画最短时长」与「`state.status === 'ready'`（store 数据就绪）」两个条件，二者皆满足后触发退出，退出动画结束再卸载并渲染主界面。
- 与现有启动逻辑（`applyTheme(getStoredTheme())`）协调：主题在开屏层即生效，退出后主界面沿用同一主题，无二次闪变。

### 7.2 Android（Capacitor）
- 原生启动屏（`@capacitor/splash-screen`，底色 `#0a0a0f`）职责调整为**仅覆盖 WebView 初始化白屏**：在 WebView ready 后立即 `SplashScreen.hide()`，把「品牌开屏」交给本 Web 动画，避免「原生静态屏 + Web 动画」双开屏割裂。
- 交接要求：原生屏底色（`#0a0a0f`）与 Web 开屏层底色（深色主题）过渡无可见白闪/黑跳；`capacitor.config.ts` 的 `SplashScreen` 配置相应调整（如 `launchAutoHide` 或改用手动 hide 时机）。
- 状态栏联动沿用 `updateStatusBar()`，开屏期间状态栏配色与主题一致。

## 8. 技术实现方案（给 Agent 的操作要求）

### 8.1 文件规划（新增/改动，均不写死新颜色，一律引用 token）

| 文件 | 职责 | 类型 |
|------|------|------|
| `src/components/SplashScreen.tsx` | 开屏组件：读取主题、渲染 SVG 光弧 + 字标、驱动阶段状态机、处理最短/最长时长与跳过、退出后卸载 | 新增 |
| `src/splash.css`（或组件内 CSS Module） | 全部动画 keyframes、双端布局媒体查询、四主题覆盖、reduced-motion 降级 | 新增 |
| `src/App.tsx` | 挂载 `<SplashScreen />`，协调 ready 条件与主界面渲染时机 | 改动 |
| `capacitor.config.ts` | 原生启动屏 hide 时机调整（交接给 Web 动画） | 改动 |
| `src/main.tsx` 或入口 | 确保开屏层在 React 首帧即可见（必要时内联首屏骨架，防白闪） | 视情况改动 |

### 8.2 组件行为契约
- Props：`onFinished: () => void`（退出动画结束回调）、可选 `minDurationMs`（默认按端取值）。
- 内部状态机：`entering → animating → holding → exiting → done`；`done` 时调用 `onFinished` 并由父组件卸载。
- 就绪条件：`动画到达最短时长` **且** `store.status === 'ready'`（或到达硬上限 2500ms）→ 进入 `exiting`。
- 端类型判定：用 `window.matchMedia('(min-width: 768px)')` 或现有响应式约定，选择桌面/手机时间轴与布局。
- 跳过：`pointerdown` / `keydown` 立即跳到 `exiting`。
- 清理：卸载时移除所有事件监听与 `setTimeout`/`requestAnimationFrame`。

### 8.3 SVG 光弧实现要点
- 用 `<circle r=... stroke-dasharray="周长" stroke-dashoffset="周长">`，通过 keyframes 把 `dashoffset` 动画到对应 300° 的偏移量（`周长 × (1 - 300/360)`），实现顺时针绘制。
- 弧渐变用 SVG `<linearGradient>`（或 `conic` 近似），stop 色引用 CSS 变量（`stop-color: var(--color-primary)`）。
- 尖端辉光：叠加一个跟随弧端的小 `<circle>` + `filter: drop-shadow(0 0 6px var(--color-primary))`；深色主题加大 blur 半径。
- 补合阶段：再对 `dashoffset` 做第二段动画至 0（完整环）。

### 8.4 性能约束
- 仅动画 `opacity` / `transform` / `stroke-dashoffset`；对动画元素设 `will-change` 但退出后移除。
- 不引入任何第三方动画/图形依赖。
- 开屏层单文件 CSS，体积可控（目标 < 6KB 源码）。

## 9. 实施步骤（分 Phase，可被 Agent 顺序执行）

> 每个 Phase 完成后自检，再进入下一 Phase。全程遵守 v55 §4.2 主题机制与 §4.6 设计债约束。

**Phase 0 — 基线确认**
- 读 v55 快照第 4 章，确认 token 名、缓动值、四主题底色与 primary 色。
- 确认 `App.tsx` 现有启动流程与 `getStoredTheme()` 用法。

**Phase 1 — 结构与静态视觉**
- 建 `SplashScreen.tsx` + `splash.css`，先渲染**静态终态**（完整环 + 字标 + 双端布局），不加动画。
- 桌面/手机两套布局用媒体查询验证到位；四主题 `data-theme` 覆盖静态呈现正确。

**Phase 2 — 动画时间轴**
- 按第 4 章分别实现桌面/手机 keyframes 与阶段状态机。
- 实现最短/最长时长、就绪条件、跳过、卸载清理。

**Phase 3 — 主题与降级**
- 四主题动画差异（辉光强度、高光手法、Neo/Paper 去柔光）。
- `prefers-reduced-motion` 静态降级；无障碍属性。

**Phase 4 — 平台集成**
- 接入 `App.tsx`，与 `state.status === 'ready'` 协调。
- Android：调整原生启动屏 hide 时机，真机验证无白闪、无双开屏割裂。

**Phase 5 — 验收与归档**
- 按第 11 章逐项验收（双端 × 四主题 × reduced-motion × 跳过 × 冷启动性能）。
- 写开发日志 `docs/logs/`、更新 `README.md` Runtime 版本号、commit 并 push（遵循项目「日志+版本+提交」工作流）。
