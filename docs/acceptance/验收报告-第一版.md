## 一、阻塞性问题（Blocking）

### 1.1 线上站点访问控制冲突
**严重程度**: 阻塞性  
**影响范围**: 所有用户  
**问题描述**:  
线上站点（my-schedule-akzzfsdx3vh.qoder.zone）要求Qoder账号登录才能访问，显示"登录后即可访问"页面。这与PRD第1.3节"仅个人使用：无注册登录、无社交功能"的要求直接冲突。

**PRD要求**:  
> 仅个人使用：无注册登录、无社交功能。  
> 部署为线上网页（Qoder Sites），数据存云端数据库；隐私靠链接不公开保护。

**实际情况**:  
站点启用了Qoder Sites的访问控制功能，要求身份验证，导致无法直接通过链接访问。

**建议**:  
关闭Qoder Sites的访问控制，或将站点设为公开访问（通过链接不公开来保护隐私）。

---

### 1.2 数据导入功能失败
**严重程度**: 阻塞性  
**影响范围**: 数据备份恢复、跨设备同步  
**问题描述**:  
在设置页面使用"导入JSON"功能时，系统报错：
```
clear semesters: invalid input syntax for type uuid: ''
```

**根本原因**:  
`functions/handler.mjs` 中 `data.import` 处理函数使用了错误的Supabase删除语法：
```javascript
// 错误代码
const { error } = await supabase.from(table).delete().filter("id", "not.is", "00000000-0000-0000-0000-000000000000");
```

**修复方案**:  
已修改为正确的Supabase JS语法：
```javascript
// 正确代码
const { error } = await supabase.from(table).delete().not("id", "is", null);
```

**当前状态**:  
修复代码已提交到本地仓库（GitHub: Jacques-Jin/My-Schedule），但多次尝试部署到生产环境均失败（task_deadline_exceeded超时），导致修复未能生效。

**影响**:  
- 无法通过导入功能恢复数据
- 跨设备数据同步受阻
- 数据备份功能形同虚设

---

### 1.3 部署持续失败
**严重程度**: 阻塞性  
**影响范围**: 所有线上功能  
**问题描述**:  
修复数据导入bug后，尝试部署到Qoder Sites生产环境，连续5次以上部署操作均超时失败：
- 错误类型: `task_deadline_exceeded`
- 失败阶段: `publish_site` 操作在"running"状态超时
- 影响: 所有前端和函数修复无法上线

**尝试的解决方案**:  
1. 多次重试 `prepare_site` + `publish_site` 流程
2. 尝试使用 `release_backend` 直接更新函数
3. 不同actionId重复尝试

**结果**:  
所有尝试均失败，部署从未完成。本地修复代码无法部署到生产环境。

## 三、体验性问题（UX）

### 3.1 日期选择器组件一致性问题
**严重程度**: 体验性  
**影响范围**: 所有日期输入场景  
**问题描述**:  
日期选择器在多个表单中表现不一致：
- 日程创建/编辑表单：日期选择器正常工作
- 学期创建/编辑表单：日期选择器无法使用
- 战役创建/编辑表单：日期选择器无法使用

**分析**:  
可能是不同表单使用了不同的日期输入组件，或组件配置不一致。

**建议**:  
统一使用工作正常的日期选择器组件（参考日程表单的实现）。

---

### 3.2 日程时间线显示逻辑
**严重程度**: 体验性  
**影响范围**: 首页时间线  
**问题描述**:  
在首页创建的"测试日程"（未设置时间），出现在"今日待办"列表中，但未在"今日时间线"中显示。

**可能原因**:  
- 无时间的日程不显示在时间线中（设计如此）
- 或时间线渲染逻辑存在问题

**建议**:  
明确PRD中对无时间日程的显示规则，并统一实现。
