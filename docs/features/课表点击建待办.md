# 课表空白时段点击新建待办 技术方案

> 状态：仅计划，未实施
> 日期：2026-09-30
> 关联功能：课表周视图、日程（tasks）、日常活动拖拽改时间

## 1. 背景与现状

### 1.1 用户诉求

「鼠标左键点击周课表任意对应时段，弹出『新建待办』的功能。」

### 1.2 现有实现盘点

| 层 | 现状（含位置） | 结论 |
| --- | --- | --- |
| 周视图单元格 | `SchedulePage.tsx:357-370` 的 `.wg-cell` 只绑了 `onDragOver` / `onDragLeave` / `onDrop`（Bug3 拖拽改时间用），**没有 `onClick`** | 加一个 `onClick` 即可，不动网格结构 |
| 课程块层叠 | `CourseBlock` 在 `SchedulePage.tsx:375-391` 渲染，**位于单元格之后**、同一 grid 容器内、无 z-index 差异 → 绘制在单元格之上，且自带 `onClick` → 课程详情 | 点击课程块不会穿透到单元格，**无需额外遮挡处理** |
| 新建日程表单 | `TaskFormSheet.tsx` 已支持 `initialData`（含 `date` / `start_time` / `end_time`）与 `defaultDate`；`initialData.id` 缺失时标题为「新建日程」且不显示删除按钮 | **组件零改动，直接复用** |
| 保存链路 | `store.saveTask` → `api.taskSave` → handler `task.save`；字段白名单已含 `start_time` / `end_time`（`handler.mjs:291`），校验只要求 `title` + `date` | **后端、数据库、迁移全部零改动** |
| 节次时间源 | `state.periodSlots`（14 节，含 `start_time` / `end_time`），本地兜底 `PERIOD_SLOTS`（`date.ts:174-189`）；周视图每一行就是一个 slot | 点击的行即已知时段，无需再算 |

**缺口只有两个：单元格没有点击入口；没有「点击的 slot → 表单预填值」的映射。**

## 2. 需求定义

- 左键**单击**周视图任意空白单元格 → 弹出「新建日程」表单
- 预填：`date` = 该列日期；`start_time` / `end_time` = 该节起止时间（如第 3 节 → `09:50`–`10:35`）
- 其余字段沿用表单默认值（分类「学习」、优先级「中」、不重复、不提醒、无归属战役、备注空）
- 保存后走既有 `task.save` 持久化，日程页与首页立即可见，刷新后仍在
- **不改变**的既有行为：点课程块 → 课程详情；拖日常活动到单元格 → 只改时间

## 3. 技术方案

### 3.1 交互边界定义

| 点击 / 操作对象 | 行为 |
| --- | --- |
| 周视图空白单元格 | 弹出新建日程表单，预填日期 + 该节时段 |
| 课程块（含跨多节的块） | 打开课程详情（不变） |
| **假期列**的空白单元格 | 同样可新建（待办是个人事项，不受放假影响），日期为该假期日 |
| 日常横带 `rb-chip` | 拖拽改时间（不变）；单击无行为 |
| 日表头 `.wg-day-head` | 本功能不绑定（**预留给「调休标记」**，避免两者抢同一区域） |
| 日视图 | 本次不做（日视图是「上午/下午/晚上」分组卡片，没有时段网格，落点不明确） |
| 移动端 | 周视图下轻触单元格同样触发（`onClick` 在触屏等价）；默认视图仍是日视图，不改动 |
| 右键 / 双击 | 不特殊处理；双击会派发两次 click → 用「表单已打开则忽略后续点击」兜住（见 3.4） |
| 键盘 | 本次不做（单元格非 focusable）；如后续要无障碍，另立需求 |

### 3.2 时段映射规则

新建纯函数模块 `src/lib/schedule-cell.ts`：

```
export interface TaskDraft { date: string; start_time: string; end_time: string }
export function cellToTaskDraft(dateStr: string, slot: { start_time: string; end_time: string }): TaskDraft
```

规则：

1. `date` = 传入的列日期（`YYYY-MM-DD`，直接来自 `datesOfWeek` 结果，不做二次换算）
2. `start_time` = `slot.start_time`；`end_time` = `slot.end_time`
3. `slot.end_time` 缺失或非法时兜底为 `start_time + 45 分钟`（与默认节次时长一致），跨零点则截断为 `23:59`
4. **一次点击 = 一节**，不自动合并相邻空节

示例（默认 14 节）：

| 点击节次 | 预填时段 |
| --- | --- |
| 第 1 节 | 08:00–08:45 |
| 第 3 节 | 09:50–10:35 |
| 第 5 节（午休前） | 11:30–12:15 |
| 第 6 节（下午第一节） | 14:00–14:45 |
| 第 14 节 | 21:30–22:15 |

> 若用户在设置页改过节次时间（`period.save`），预填值自动跟随 `state.periodSlots`，因为映射直接读 slot 对象。

| 位置 | 改动 |

**关键约束（最容易踩的坑）**：`initialData` **必须来自 state 的稳定引用**。`TaskFormSheet` 的初始化 `useEffect` 依赖 `[open, initialData, defaultDate]`（`TaskFormSheet.tsx:89-119`），若写成内联字面量 `initialData={{ date: d, start_time: s }}`，父组件每次重渲染都会生成新对象 → effect 重跑 → **用户正在输入的标题被清空**。`TasksPage.tsx:300-309` 传的是 state 值 `editingTask`，本功能必须照此办理。

### 3.4 与拖拽 / 双击的冲突处理

- HTML5 DnD 语义：`dragstart` 之后浏览器不再派发 `click`，正常路径本身无冲突
- **保险 1**：`onClick` 内 `if (dragTask.current) return;`（拖拽进行中不弹表单）
- **保险 2**：`rb-chip` 增加 `onDragEnd` 清空 `dragTask.current`（现状只有 `handleDrop` 会清，拖拽被取消会残留状态，导致之后第一次点击被吞）
- **保险 3**：`taskFormOpen === true` 时忽略新的单元格点击（防双击叠开 / 防表单被重置）

### 3.5 视觉反馈

- `.wg-cell` 增加 `cursor: pointer`
- hover：极浅底色（复用 `--color-primary-light` 或 `rgba` 低透明度）+ 居中半透明「+」（`::after`，`pointer-events: none`）
- 假期列单元格保留现有红底 `.holiday-cell`，hover 态可叠加
- **不改** grid 定义、行高、列宽、`.course-block` 定位，避免课程块漂移

### 3.6 否决的备选方案

| 方案 | 否决理由 |
| --- | --- |
| 右键上下文菜单 | 用户明确要求左键；移动端无右键 |
| 双击新建 | 与「单击课程块看详情」的单击语义不一致；移动端双击体验差且易误触缩放 |
| 单元格内联输入标题 | 需要新组件 + 焦点/键盘管理，且无法设置分类、提醒、战役、重复规则，能力弱于复用 `TaskFormSheet` |
| 拖选多节一次性新建 | 与日常活动拖拽手势冲突；超出本次诉求（可作为后续增强） |
| 日视图同时支持点击新建 | 日视图无时段网格，落点不明确；本次范围仅周视图 |
| 新建一个「轻量待办弹窗」组件 | 与 `TaskFormSheet` 功能重叠，维护两套表单；直接复用成本更低、体验一致 |

## 6. 验收方案

### 6.1 验收标准

1. 周视图点击任意空白单元格弹出「新建日程」表单，日期 = 该列日期，开始/结束时间 = 该节时段
2. 在表单里输入标题的过程中（父组件发生重渲染时）**已输入内容不被清空**
3. 填写标题保存后 Sheet 关闭，日程页该日期下出现这条待办，时段与点击的节次一致
4. 刷新页面后待办仍在（走既有 `task.save` 持久化）
5. 点击已有课程块（含跨多节的块）仍打开课程详情，**不弹**新建表单
6. 从日常横带拖拽活动到某单元格只改时间，**不弹**新建表单；拖拽被取消后首次点击仍能正常弹表单
7. 快速双击同一单元格只弹出一个表单，不出现表单被重置或叠加
8. 假期列的空白单元格点击同样可新建，日期为该假期日
9. 取消 / 按 Esc / 点遮罩关闭表单，不产生任何数据
10. 单元格 hover 显示指针与「+」提示，课程块显示与网格对齐不受影响
11. 移动端 375px 周视图轻触单元格可弹出表单，表单不横向溢出
12. 回归：`phase1–8` 全绿（基线 284 项），日程页 / 首页 / 战役页的新建日程入口行为不变

## 7. 工作量与风险

- **工作量**：约 2–3 小时（纯前端 + 少量测试，无迁移、无后端）
- **风险 1｜`initialData` 引用不稳定导致表单被重置**：draft 必须存 state；手工用例 2、8 专门覆盖
- **风险 2｜点击与拖拽互相干扰**：三重保险（3.4）+ 用例 6、7 覆盖
- **风险 3｜hover 样式影响课程块视觉或网格对齐**：只改背景与 `::after` 伪元素，不动布局；用例 5、10 覆盖
- **风险 4｜与「调休标记」同时改 `SchedulePage.tsx`**：两功能都动 `WeekView`，**必须串行实施**，不可并行开发后合并
- **风险 5｜假期列可点击是否符合预期**：本方案定为「可以」（待办属个人事项）；若用户希望假期列不可点，仅需在 `onClick` 中按 `DayType.isHoliday` 提前返回，改动量 1 行

## 8. 与「调休标记」的实施顺序建议

1. **先做本功能**：零数据库迁移、改动集中在 `SchedulePage.tsx` 一个文件、2–3 小时可完成并上线
2. **再做「调休标记」**：需迁移到 `schema_version = 4`，改动面覆盖 `date.ts` / `store.tsx` / `handler.mjs` / 三个页面，约 1 天
3. 两个功能各自独立 commit、独立部署与线上验证，避免一次上线两个变更导致问题难定位
4. 若用户要求先做「调休标记」，本功能的测试文件顺延为 `tests/phase10.mjs`，其余方案不变
5. 两者唯一的耦合点是 `WeekView`：日表头点击归「调休标记」，单元格点击归本功能，区域不重叠
